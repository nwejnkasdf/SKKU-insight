# SRS §4.2. Acceptance Test Scenarios

본 파일은 SRS v0.3 §4.2 (AT-01~15, Table 9)를 분할한 것이다. 자동화 가능 항목과 수동 항목 분류는 구현 계획에서 결정됐다.

## Acceptance Test Scenarios (Table 9)

| ID | 시나리오 | 기대 결과 | 자동화 |
|---|---|---|---|
| AT-01 | 신규 사용자가 일반 이메일과 비밀번호로 가입한 뒤 로그인한다. | 시스템은 계정을 생성하고 로그인한 사용자의 관심 상태, 피드백, 설정 데이터를 연결한다. | 자동(pytest+vitest) |
| AT-02 | 신규 사용자가 이메일 가입 중 개인화 데이터 수집에 동의하지 않는다. | 시스템은 회원가입 또는 초기 설정 완료를 차단한다. | 자동(pytest) |
| AT-03 | 사용자가 설정 화면에서 필수 개인화 동의를 철회한다. | 시스템은 계정을 유지하되 추천 대시보드와 개인화 기능을 중단하고 재동의, 설정, 계정 삭제 화면만 제공한다. | 자동(pytest+vitest) |
| AT-04 | 후보가 충분한 사용자가 대시보드를 조회한다. | core 5개, adjacent 3개, discovery 2개로 총 10개 추천이 표시된다. | 자동(pytest, 시드 페르소나 사용) |
| AT-05 | 특정 슬롯의 신뢰도 기준 충족 후보가 부족하다. | 시스템은 저신뢰 후보를 강제하지 않고 다른 슬롯 후보로 대체하며 실제 슬롯 수와 fallback 사유를 기록한다. | 수동·시연 (시드 데이터 조작) |
| AT-06 | 전체 개인화 후보가 10개보다 부족하다. | 시스템은 상위 토픽 인접 범위와 신뢰 소스 전체 트렌드로 fallback을 확장해 총 10개 추천을 표시한다. | 수동·시연 (격리 페르소나) |
| AT-07 | 사용자가 추천 문서를 열람하고 저장, 숨김, 관심 없음 중 하나를 선택한다. | 해당 피드백과 행동 로그가 관심 상태 업데이트 입력으로 저장된다. | 자동(pytest) |
| AT-08 | 낚시성 필터를 통과한 테크 뉴스가 사용자 관심 토픽과 관련 있다. | 시스템은 해당 뉴스를 학술 소스 및 빅테크 공식 채널과 동등한 추천 후보로 사용한다. | 자동(pytest) |
| AT-09 | 뉴스/기사성 2차 문서가 낚시성으로 판정된다. | 해당 문서는 추천 후보에서 제외되고 관리자 통계에 반영된다. | **(v13 라운드)** 사용자 News 소스 명시 활성화 케이스에 한해 자동(pytest, mock 분류기). 1차 시연 default 비활성. |
| AT-10 | 사용자가 문서 상세 화면을 연다. | 섹션형 생성 요약과 짧은 토픽 근거가 표시되고 행동 로그/관심 점수는 노출되지 않는다. | 수동·시연 |
| AT-11 | 같은 문서가 동일 URL, DOI, 또는 유사 제목으로 중복 수집된다. | 시스템은 중복 문서를 대시보드에 반복 추천하지 않는다. | 자동(pytest) |
| AT-12 | 사용자가 계정 및 개인화 데이터 삭제를 요청한다. | 시스템은 신규 개인화 처리를 중단하고 계정, 행동 로그, 관심 상태, 저장/숨김 기록 삭제 요청을 처리한다. | 자동(pytest) |
| AT-13 | 일반 사용자가 관리자 웹 콘솔에 접근한다. | 시스템은 접근을 차단한다. | 자동(pytest) |
| AT-14 | 사용자별 수집 작업이 실패한다. | 관리자 웹 콘솔에 사용자별 실패 로그가 표시되고 재실행 요청이 가능하다. | 수동·시연 |
| AT-15 | 에이전트가 사용자별 동적 리프 토픽을 생성한다. | 시스템은 해당 리프 토픽을 사용자 계정 및 하나 이상의 상위 CSO 토픽에 연결하고 상태를 기록한다. | 자동(pytest+mock LLM) |
