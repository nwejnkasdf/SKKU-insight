# 국제화 (i18n) 정책

본 파일은 SKKU InSight의 한·영 콘텐츠 처리 룰을 정의한다. 결정 매트릭스 §1 "UI 한국어 / 콘텐츠 한·영 병행, 요약·추천 이유는 한국어"를 구체화. 관련 NFR: NFR-23 (한국어 산출물).

## 결정

- **UI 라벨/메시지**: 한국어 단일
- **콘텐츠 (문서 제목 / abstract)**: 원문 그대로 (영어 또는 한국어). 의역 X
- **LLM이 생성하는 요약·추천 이유**: 한국어 (medium 모델로 생성 시 한국어 강제)
- **검색·필터**: 영어 키워드도 매칭 가능 (단순 대소문자 무관 string contains + Levenshtein)

## 라이브러리

- 클라이언트 (Electron): `react-i18next` + `i18next`
- 관리자 콘솔 (Next.js): `react-i18next` (App Router 호환) 또는 `next-intl`. 1차는 `react-i18next` 통일.

## 키 네이밍 규칙

```
<scope>.<feature>.<state>.<element>

예:
  auth.signup.title
  auth.signup.button.submit
  auth.signup.error.email_taken
  dashboard.card.action.save
  dashboard.empty.banner_message
  settings.consent.revoke.confirm_title
  admin.collection.empty.normal_operation
```

## 클라이언트 (Electron) 구조

```
client/src/locales/
└── ko/
    ├── common.json
    ├── auth.json
    ├── dashboard.json
    ├── topic.json
    ├── document.json
    ├── settings.json
    └── error.json
```

미래 (EV 단계 글로벌 확장 시) `en/` 추가 가능. 1차는 `ko/`만.

## 관리자 콘솔 구조

`admin-console/locales/ko/`에 동일 패턴.

## 콘텐츠 다국어 노출

문서 카드/상세 화면에서:

```
+----------------------------------------+
| 한국어 의역 제목 (있으면)              |
| English Original Title (subtle)        |
+----------------------------------------+
```

원문이 한국어면 한국어만, 영어면 한국어 의역(LLM 생성) + 영어 원문 작은 글씨.

`Document.title`은 원문, `Document.title_ko`는 LLM이 생성한 한국어 (medium 모델). 1차 시연에서 의역이 없는 카드는 영어 원문만 그대로 노출 (자연스러움).

## LLM이 생성하는 한국어

```
System: "응답은 모두 한국어로 작성한다. 외국어 고유명사는 그대로 사용한다."
```

**고유명사 보존**:
- "Google DeepMind" → 그대로
- "Diffusion Model" → 그대로 또는 "확산 모델 (Diffusion Model)"
- 기술 용어는 첫 등장 시 한국어 + 영문 괄호 표기 권장

검증: 응답 텍스트의 한국어 비율 >= 60% (정규식 한글 unicode block 기준).

## 시스템 메시지 vs 사용자 메시지 분리

- **시스템 로그 / 에러 코드**: 영어 (예: `auth.invalid_credentials`)
- **사용자에게 노출되는 메시지**: 한국어
- **API 응답의 `message` 필드**: 한국어 (사용자 표시용)
- **API 응답의 `code` 필드**: 영어 (i18n 키처럼 작동)

```python
class ErrorResponse(BaseModel):
    code: str         # "auth.invalid_credentials"
    message: str      # "이메일 또는 비밀번호가 올바르지 않습니다."
```

클라이언트는 `code`로 i18n key를 찾아 표시하고, `message`는 fallback으로 사용.

## 날짜·시간 포맷

- 사용자 화면: 한국어 형식 ("2026년 5월 9일 14:30") 또는 상대 시간 ("3시간 전")
- 라이브러리: `date-fns/locale/ko` 또는 `dayjs/locale/ko`
- API/DB: 항상 ISO8601 + UTC

## 관리자 콘솔

관리자도 한국어 UI. 다만 토픽 라벨(영어 원문)과 LLM 응답 일부는 영어 그대로 — 운영자가 원문을 더 잘 이해하기 위함.

## 향후 확장

EV-04 단계로 영어 UI를 추가하려면:

- `i18next-browser-languagedetector` 도입
- `client/src/locales/en/`, `admin-console/locales/en/` 추가
- 사용자 설정 (UI-05)에 언어 선택 추가
- API 응답의 `message`도 영어 버전 추가 또는 `Accept-Language` 헤더 기반 선택

1차는 한국어 단일.

## 검증

- pytest 또는 vitest: 모든 i18n 키가 사용되는지, 누락된 키가 있는지 확인 (`i18next-parser` + check)
- 자동: 모든 사용자 노출 문자열이 i18n key 통해 출력되는지 grep (하드코딩 한국어 검출)
