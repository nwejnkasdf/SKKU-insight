# UI 상태 카탈로그 (빈/오류)

본 파일은 SRS UI-01~06의 빈 상태·오류 상태를 단일 표로 정리한다. 와이어프레임 인덱스와 화면별 상태 머신은 [`wireframes.md`](wireframes.md), 한국어 i18n 룰은 [`i18n.md`](i18n.md). 한국어 메시지는 1차 시연용 초안이며, A9·A10가 i18n 키로 옮긴다.

## 빈 상태 (Empty State) 카탈로그

| 화면 | 트리거 조건 | UI 표현 | 액션 |

| UI-01 온보딩 | 관심 분야 선택 0개 | 시작 버튼 비활성 | 클러스터 1개 이상 선택 후 활성 |
| UI-01 온보딩 | 동의 미체크 | 시작 버튼 비활성 | 동의 체크 후 활성 |
| UI-02 대시보드 | 추천 후보 < 10 | 모든 카드는 항상 10개 (FR-43 fallback). 일부에 "최신 트렌드" 배지 | 카드 클릭/토픽 칩 |

|---|---|---|---|
| UI-01 | 이메일 형식 부정확 | "올바른 이메일 형식이 아닙니다." | 즉시 입력란 표시 |
| UI-01 | 이메일 중복 (auth.email_taken) | "이미 가입된 이메일입니다." | 로그인 화면 링크 |

| UI-01 | 429 rate_limited | "잠시 후 다시 시도해주세요." (Retry-After) | 시간 표시 카운트다운 |
| UI-02 | 5xx | "추천을 가져오지 못했어요. 마지막 추천을 보여드릴게요." (cached banner) | 자동 재시도 (지수 백오프) |
| UI-02 | 403 consent_required | (UI-05로 redirect) | 재동의/삭제 |
| UI-02 | 202 cold_start_in_progress | "맞춤 추천을 준비하고 있어요…" 스피너 | 1초 폴링 |
| UI-03 | 422 topic.linkage_error | "토픽 정보를 불러올 수 없어요. 대시보드로 돌아가시겠어요?" | "대시보드로" 버튼 |
| UI-04 | 503 summary_unavailable | "요약을 가져오지 못했어요. 출처의 초록을 표시합니다." | 출처 abstract |
| UI-04 | 원문 링크 4xx/5xx | "원문에 접근할 수 없어요. {source_name}에서 직접 확인해 주세요." | 외부 링크 재시도 |
| UI-05 | 5xx 동의 철회 실패 | "처리에 실패했어요. 다시 시도해주세요." | 재시도 |
| UI-05 | 5xx 계정 삭제 실패 | "삭제 요청이 실패했어요. 잠시 후 다시 시도해주세요." | 재시도 + 고객 지원 안내 |
| UI-06 | 401 admin role 부족 | "이 작업을 수행할 권한이 없습니다." | (없음) |
| UI-06 | 409 admin.must_change_password | (강제 변경 모달) | 변경 후 닫힘 |
| UI-06 | 409 reprocess_already_queued | "이미 재실행 요청이 처리 중입니다." | 진행 상태 보기 |
| 공통 | 네트워크 단절 | "인터넷 연결을 확인해 주세요." (오프라인 배너) | 자동 재시도 |
| 공통 | 401 token_expired | (자동 refresh 시도) → 재실패 시 로그아웃 | 재로그인 화면 |

## 로딩 상태

| 화면 | 트리거 | 표현 |
|---|---|---|
| UI-02 | 캐시 hit | <100ms 깜빡임 없음 |
| UI-02 | 캐시 miss | 스켈레톤 카드 10개 |
| UI-02 cold-start | 첫 사용자 | 풀스크린 "맞춤 추천을 준비하고 있어요…" + 무한 스피너 (max 8s 후 폴링) |
| UI-04 | 문서 상세 + 요약 | 헤더는 즉시, 요약 영역만 스켈레톤 |
| UI-06 | 관리자 잡 목록 | 테이블 스켈레톤 5행 |

## 빈/오류 → 행동 가능 보장

모든 빈/오류 상태는 사용자가 다음 행동을 취할 수 있어야 한다:

- 빈 상태: 다음 행동 안내 또는 닫기/뒤로
- 오류 상태: 재시도 버튼 또는 대안 동작 (대시보드로/외부 링크)
- 로딩 상태: 취소 가능 또는 백그라운드로 전환

## 토스트 / 인라인 메시지 사용 룰

- **토스트** (auto-dismiss 4s): 카드 액션 결과 (저장됨/숨김 처리됨/관심없음 처리됨)
- **인라인** (사용자 닫기 전 유지): 폼 검증 오류, 5xx 오류
- **풀스크린 모달**: 동의 철회 확인, 계정 삭제 확인, 비밀번호 강제 변경

## 한국어 메시지 톤

[`i18n.md`](i18n.md)의 룰:

- 사용자에게 친근한 어투 ("…해 주세요"). 명령형 회피.
- 기술 용어는 가능하면 한국어로. 영어 원문이 더 명확하면 (예: API, JSON, RSS) 그대로 사용.
- 점수, 알고리즘, 모델명은 사용자 메시지에 포함하지 않는다 (NFR-04).
